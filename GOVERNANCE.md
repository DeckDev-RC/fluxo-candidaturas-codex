# Governança

## Mantenedor

O projeto é mantido por `@DeckDev-RC`. O mantenedor define roadmap, revisa pull
requests, publica releases e aplica o Código de Conduta.

## Decisões

- Correções e mudanças pequenas seguem issue e pull request.
- Alterações de arquitetura, política, dados transmitidos ou dependências
  estruturais começam em uma discussão pública.
- Segurança pode ser tratada privadamente até a correção.
- Divergências são resolvidas pelo mantenedor com justificativa técnica.

## Merge

Um pull request precisa de CI verde, DCO, revisão de segurança proporcional ao
risco, dados sintéticos e documentação atualizada. O mantenedor pode solicitar
mudanças ou encerrar propostas incompatíveis com o escopo.

## Releases

Releases saem de tags `v*`, com testes, checksum, SBOM e proveniência. A ausência
de assinatura Authenticode deve ser informada. Incidentes podem gerar retirada
temporária de um artefato.

## Novos mantenedores

Pessoas com contribuições recorrentes, revisão cuidadosa e alinhamento ao Código
de Conduta podem receber responsabilidades graduais. A decisão e o escopo serão
registrados publicamente.
